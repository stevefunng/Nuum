# 群聊连续性与通用 compact

2026-10-16，本轮实现与最终复验说明。客户端同步水位、讨论循环和卡片业务流程保持原有职责。

## 群聊输入

主 session 最新 user/wake 属于同房间、成员 revision 相同且输入 epoch 等于当前 compact epoch 时，追加上次输入之后的公开消息。否则补最近 24 条；明确选择历史范围时尊重用户选择。本次触发消息在重建背景时必含，连续模式已输入过的触发不重复加入。assistant、工具结果不打断连续性。旧记录缺少 epoch 保守补背景。

每次输入持久保存 mode、epoch、房间、范围和消息 ID。它是执行证据，不是永远禁止重新输入的水位。compact 后可有意再次提供原文；公开房间日志不会产生第二份气泡。房间很久以前的决定仍可能超出窗口，需 ReadWorkTimeline 查证。

## 压缩职责

Host 拥有历史和 checkpoint；Kernel 执行模型调用，使用 turn.context / turn.provideContext 在每次模型请求之前等待 Host。

- 启动前超过窗口 75% 进行同步压缩，仍超限则拒绝启动。
- 长 run 每次请求前按完整消息、工具定义、图片预留估算容量。80% 开始后台准备；摘要就绪在下一个调用边界应用，达到 85% 则等待准备结果；90% 仍无法容纳则停止请求。因为目前只有保守估算，采用比 Grokbot 90% / 95% 更早的余量，正常输出上限为窗口 10% 与 4096 的较小值。
- 估算是共享的 protocol 工具，不是精确 tokenizer；图片按每张 8192 tokens 预留，无法证明适合所有模型。
- 摘要 job 固定 session、原 epoch 和截断点；每个活动 run 至多一个。同 Nunu 单槽保证同 session 不并发生成多个 job。
- 默认保留最后 user/wake 及之后历史。长 run 必要时按 assistant 边界切掉较早已完成步骤，当前请求原文另存 activeRequest 并补回。
- 应用时再次检查 job 身份、run 存活、取消及 epoch。只追加 compact checkpoint，截断点后的新事件完整保留，不改原 JSONL。
- Kernel 只在工具批次结束、下一次模型请求前替换消息；保留 Kernel 内的图片和提醒。不重跑工具。保留的图片本身过大时可能停止执行，而不是静默丢图。
- run 结束、取消和 Host 退出取消摘要；过期返回不落盘。摘要任务不跨进程重启恢复。

## 摘要输入与失败

待压缩前缀序列化为带角色／身份的引用证据，每块最多 24,000 字符、最多 16 块；逐块摘要后以每组最多三个摘要归并。不会静默丢掉前缀末尾。单次调用超时 30 秒、输出上限 1024 tokens，失败最多再试一次并降低到 768；大于 6000 字符或空摘要拒绝。job 在 120 秒期限后不再启动新调用，因此总耗时可能再包含最后一次调用的超时时间。

取消通过 summarize.cancel 终止当前摘要模型请求。失效 job 即便有迟到结果也不能提交。达到安全容量却无法压缩时明确报错，不带已知超限 context 继续请求。

摘要要求区分私人对话和各房间的决定、承诺、待办、消息引用，继承上一份摘要中仍有效的事项。身份、权限、当前卡片及能力从原有 system prompt 真源重新装配，没有新增独立房间摘要数据库。摘要有损，不保证所有关键事实永久保留。

## 验证

自动测试覆盖：连续性与回群背景、长 run 安全切分、每轮 context 握手、失败／取消禁止模型请求、后台期间新增结果保留、迟到摘要不提交、分块末尾不丢、有限重试。全量测试、类型检查、依赖检查和 Host 进程冒烟通过。实际 Electron 中检查了个人会话参与提示；模型成功压缩和语义质量依赖模拟 Kernel 验证，未做真实模型质量评测。

Kernel 断连时关闭 RPC peer，拒绝所有挂起及后续请求，避免 context 握手／摘要悬挂；已加入连接关闭回归。
