# 本地执行 daemon 实施记录

> 本文保留阶段验收历史；当前架构和产品行为以[沙箱文档](../sandbox/README.md)为准，尤其审批规则已于 2026-10-22 更新。

状态：2026-10-20 已补齐授权接管、原会话结果恢复及房间审批端到端验证；最终 305 项测试、类型/依赖检查和 Desktop 构建通过。进程清理仍采用与本地 Grokbot 重建源码同类的进程组尽力清理，不具备“任意脱离进程组后代都保证销毁”的强保证，详见下文。未引入虚拟机或新锁。

## 收尾复核与修复

- 已修复：接管比较 Host 生成的授权配置摘要、命令策略、工作区 ID/根路径、房间成员代际与能力目录版本。失效上下文先停止执行并轮换凭证，再处理其已有结果。
- 已修复：daemon 为每次请求保存 Host 确定的原 run/房间/卡片 session；恢复输出写入原 JSONL 会话后才确认接收。未交付结果阻止空闲替换/回收。按稳定 executionId 去重，卡片输出不写入私聊，已收到的 Kernel 事件先处理再恢复。仍不重放模型回合、不自动执行不确定命令。
- 已实测的限制：独立后台子进程可在原进程组关闭后存活；受限文件/网络策略仍随它继承，但可能继续消耗资源或修改工作区。复现使用 Node 的 detached 子进程，测试最后按已记录 PID 清除。没有把未验证的 PID 扫描或全用户信号广播作为“修复”加入产品。
- 已补验收：真实 Electron 房间展示网络审批，点击记住后实际 HTTPS 请求成功；资料卡撤销后再次请求被拒绝并重新显示审批，点击拒绝后不保存授权。模型用确定性响应替身，Host、Kernel、daemon、Seatbelt、TLS 校验和 UI 均为实际实现。
- 端到端验证额外发现并修复系统 CA 文件读取问题：允许系统 `/etc` 只读路径（含 `/etc/ssl/cert.pem`），不关闭 TLS 校验。此前只允许 `/private/etc` 不足以覆盖实际访问。
- 未使用正式用户数据做迁移验收。

## Grokbot 的进程清理证据

本地重建仓 `source/packages/shell-exec/core.ts:32` 的取消路径向进程组发 TERM，并安排后续 KILL；非 detached 进程则向子进程发信号。`killDetachedProcessGroup` 仍按原进程组发送信号。`zsh.ts:180` 在退出后输出管道未关闭时等待约 5 秒，再杀原进程组。`host/local-exec/local-exec-provider.ts:132` 将取消请求交给执行器并 abort。源码明确将取消称为 best-effort。

这些机制不证明 `setsid` 等脱离组后代必然结束；Box daemon 的 TERM/KILL 也不能等同于销毁整个 Box。以上仅是重建源码可确认的行为，不宣称已验证官方版全部实现。Nuum 本期没有因这个边界扩展成虚拟机架构，也不把这种限制描述成工作区权限逃逸。

## 边界

- Host 是工作区、配置和授权真源，并监督应用级执行 daemon。
- Kernel 保留模型循环；文件、搜索、shell 迁到 daemon 的受限工具进程。Host 的 RunWorkCLI 同样不得绕过执行边界。
- OS 隔离才是文件、网络限制；daemon 本身不是隔离机制。隔离不可用时拒绝执行。
- 不新增目录锁、文件锁、分布式锁。保留原有 Host 单实例约束、每 Nunu 执行槽和重叠工作根互斥；不能因调用方断连提前释放仍在执行的工作根。

## 生命周期

依据本地 Grokbot 的 supervisor.ts、local-exec-provider.ts、exec-daemon-process.ts：

- 连接断开与显式取消分开；已接受的执行不因 Kernel 或监督连接短暂断开立即终止。
- daemon 有实例身份和私有认证端点；Host 恢复时核验身份，接管有进行中执行的实例，空闲实例可替换。不能仅凭 PID 杀进程。
- 监督器停止监督与应用显式退出是不同操作。意外退出时有限重启，不能重放不确定命令。
- 请求具有稳定执行 ID、可查询终态及有界输出。重连查询原执行，不重新执行相同请求。
- 显式取消、权限撤销和退出清理隔离进程组；先 TERM，约 2 秒后 KILL。普通 shell 后台子进程与 daemon 崩溃清理已有真实测试；不宣称进程组等价于 Linux cgroup，也未证明恶意脱离进程组的所有后代必然清除。
- 本地孤儿实例只保留已接受的执行，不接受未经有效 Host 授权的新执行；恢复接管仍需验证原工作区和授权。

## 工作区与配置

- 默认个人目录为系统文稿目录/Nuum/<Nunu 名称>；房间为文稿/Nuum/Rooms/<房间名称>。稳定 ID 绑定，重名加后缀，改名不自动移动。
- 房间任务只使用共享房间目录，不自动获得个人目录；同房间成员授权各自独立。
- 历史实例统一分配新目录，保留旧文件，不移动或删除。
- 扩展已有每 Nunu settings.json，不在可执行工作区存安全配置。默认断网，授权绑定 Nunu、工作区和网络目标。
- 资料卡下方提供工作区与权限 widget；不在客户端设置重复保存当前 Nunu 目录。

## 具体实现与边界

- `executor-client.ts` 是 Host 监督器；`executor/server.ts` 管上下文与认证，`ledger.ts` 管请求去重、审批与结果，`runner.ts` 管隔离工具进程。Kernel 仅持上下文凭证，无 Host 管理凭证。
- 应用级 daemon 只有一个。每个活跃执行上下文有隔离 helper/worker，用来隔开 sandbox-runtime 的进程级全局配置和网络代理，不是每 Nunu 各起一套应用 daemon。
- 使用固定版本 `@anthropic-ai/sandbox-runtime@0.0.80`；macOS 底层是 Seatbelt（由 sandbox-exec 装载策略）和限制目标的代理。它不是 VM；系统运行库与工具所需的只读路径仍可访问，工作区外的用户文件默认不可访问。其他 OS 当前拒绝执行，无降级直连。
- 网络工具 `request_network({target})` 只接受精确 `主机:80` / `主机:443`。单次允许作用于当前执行上下文；记住则保存到 Nunu settings.json 的对应 workspaceId。不是任意端口、通配域名或关闭沙箱的授权。
- `update_state` 删除 settings 分支；模型不能修改工作区/安全配置。文件、搜索、shell 的现有输入用途不变，执行位置迁往 daemon。`RunWorkCLI` 也使用同一边界。提示词随实际工作区、命令权限和网络申请方式更新。
- 监督每秒检查，连续故障最多尝试 5 次，另限制一分钟内最多 5 次重启；活着但无法认证的进程不强制替换。失去 Host 监督超过 5 秒拒绝新请求；已接受执行继续，没有未确认结果的空闲孤儿约 30 秒后退出。不同于 Grokbot 的云端 SSE，本地传输使用私有 Unix socket。
- Kernel/Host 重启后不重放模型 turn，不自动重新执行不确定命令。存活 daemon 的完成结果补回原会话并确认后，撤销旧权限。daemon 自身崩溃会丢失未交付内存结果，当前没有跨 daemon 崩溃的持久恢复服务；未知结果不得自动重跑，模型回合仍需用户显式继续。
- 新增的 policy/origin 和 JSONL executionId 是 Host/执行协议元数据，不是模型可修改的授权或工具参数。没有为恢复增加第二份会话日志。
- 结果与去重记录有容量限制（128 个未确认结果、10 万条已确认 ID），超限拒绝新执行，不静默遗忘再重放。
- 没有新增目录锁、文件锁或分布式锁。保留 Host dataDir 单实例锁、Nunu 执行槽和共享根调度约束；配置写入复用 AgentStore 原有串行写入链，未引入第二套锁。后台 shell 本身不额外占据房间目录锁。
- 不包含云端 Gateway、云端模型循环、远程桌面或远端认证服务；跨进程执行协议为将来远端执行保留边界。
