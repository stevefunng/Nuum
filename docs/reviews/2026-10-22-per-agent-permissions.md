# Per-agent 权限与外部操作改动

> 长期维护说明已整理至[沙箱技术架构与产品规则](../sandbox/README.md)；本文保留本轮实施与验收记录。

本轮在既有本地执行 daemon 上调整授权产品逻辑；不新增 daemon、目录锁、文件锁或分布式锁。旧 NunuBar UI 删除项与头像工作保持。

## 产品和执行行为

- 审批按钮为「单次允许／始终允许／拒绝」。模型的 justification 是主文案；实际资源为次级信息，命令、cwd 和规则放在可展开的执行详情中。没有额外的冗长范围提示。
- 工作区内普通工具与 shell 不再逐条询问。OS 文件／网络边界继续生效；资料卡可以停用命令执行。
- 新增 external_operation，支持 read、import、export 和 shell。文件工具只操作单个普通文件；默认导出使用排他创建，不覆盖目标。resourceRoot 可以明确申请目录范围，目录导出只允许新增文件。
- 外部 shell 是一次性受限执行，声明额外 readPaths、writePaths 和可选 networkTargets。一次操作的文件和网络权限在同一审批中展示。外部权限不会扩散给普通持久 shell。
- 所有本机目标必须位于用户主目录内的明确路径；不能直接申请整个主目录。Nuum 的 Host 数据目录及 Desktop 私有配置／密钥目录不能授权给工具。路径规范化并在执行前再次核验，OS 沙箱限制实际访问。

## 长期规则

- 规则保存在当前 Nunu 的 settings.json.execution.externalGrants；以 local 环境、工作区、操作、资源范围、必要命令规则和脚本／可执行文件摘要匹配。可以跨任务及重启复用，其他 Nunu 不继承。
- 文件授权支持精确文件与显式目录范围；读权限不能转换成写权限。目录导出允许不同文件名，不能覆盖或删除已有文件。
- Shell 以参数规则匹配，不使用根命令放行。当前明确支持泛化的语法是 git status 的常见输出选项，以及 gh pr view 的 PR 编号、--comments、--json、--repo。其他静态调用保持精确命令。
- 简单的 &&、||、;、管道链逐段形成规则，保留连接符，所有部分都必须匹配。重定向、命令替换、动态展开或无法识别的调用仅支持单次批准；「始终允许」禁用并有说明，不猜测宽泛规则。
- 直接引用的普通文件参数和可执行文件会计算内容摘要；变化后旧规则不覆盖。并不声称冻结整个脚本依赖图：最终访问能力仍由 OS 资源权限限定。
- 网络目标精确到 hostname:80/443；不能因命令匹配而获得任意联网权限。
- 旧 commandGrants 保留为原有 workspaceId + 完整命令记录，不推导外部路径或更宽命令规则。普通工作区命令已免审批，因此这些旧记录不再扩大任何能力。

## 拒绝、恢复和撤销

- 拒绝结束当前请求；同一任务的相同操作不重复弹窗，理由变化、对象字段顺序、普通命令的等价引号不产生新授权机会。
- 拒绝记录以 Host 确定的任务归属隔离：私聊关联用户指令；讨论关联讨论身份；卡片关联卡片与最近一次用户明确派发／继续执行事件。自动重试、agent 派发不自行清除当前用户任务的拒绝。
- 单独的新任务可以重新申请。用户重新派发／继续卡片可产生新审批机会，但不会自动执行之前被拒绝的请求。
- JSONL 工具结果记录 permissionTaskKey，Host 从原会话恢复当前任务的拒绝记录；daemon 内重复请求检查与 Host 恢复使用同一操作标识。没有新增第二份会话日志。
- 资料卡撤销授权会撤销原执行上下文。用户长期批准后同步持久配置与 daemon policy 摘要，避免恢复时误判新授权。
- 迟到审批只能处理仍处于 approval 状态的请求，不复活已取消或拒绝的请求。

## 代码目录

- protocol：permission-rules.ts、execution.ts、domain.ts、审批事件及 transcript 元数据。
- tools：external-tool.ts、network-tool.ts 的 justification 与参数 schema。
- executor：external-access.ts、server.ts 的审批／拒绝处理、worker.ts 的专用文件和一次性 shell 执行、runner.ts 的额外路径限制。
- host：runtime.ts 的持久规则、任务身份、恢复与撤销；prompt.ts 描述新的工具与权限边界。
- desktop：传递私有配置目录保护范围，转发审批理由与详情。
- ui：execution-approval.tsx、execution-widget.tsx、私聊／房间审批传递及文案。

## 验证

- 311 项包测试通过，Host stdio 与父进程退出冒烟通过。
- 类型检查、依赖边界与 Desktop 构建通过。
- 实际 macOS daemon + Seatbelt：单次导出、长期复用、目录内不同新文件复用、覆盖拒绝、工作区工具越界拒绝、任务内拒绝与新任务重新申请、授权期间路径变成符号链接、脚本内容变化、动态命令禁止长期批准。
- Host 集成：本机授权写入当前 Nunu 配置，撤销使旧上下文凭证失效。
- Electron 独立 QA：模型使用确定性 fixture，Host、Kernel、daemon、OS 沙箱和 UI 均为实际实现。实际点击「始终允许」完成导出，再从资料卡撤销；默认覆盖保护也实际触发。撤销后再次申请，点击「拒绝」后模型重复请求被任务内拒绝记录拦回，没有再次弹窗；浅色窄窗口展示已检查。没有使用正式用户数据。

原实施记录中的 macOS 平台限制、daemon 内存结果持久性边界，以及主动脱离进程组后代的尽力清理限制不变。本轮没有引入云端或虚拟机。
