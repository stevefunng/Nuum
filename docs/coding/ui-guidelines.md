# Nuum UI 规范

本规范约束 Nuum 桌面端的视觉、交互和 UI 数据边界。

目标不是逐像素复制另一个产品，而是在 Nuum 的产品模型上保持一致的 Grokbot-like 视觉语言：紧凑、清晰、原生、低噪音。

## 1. 参考源优先级

发生视觉歧义时，按以下顺序判断：

1. 用户当前明确提出的产品要求。
2. Grokbot 本地复刻仓中的实际组件、生成样式和运行时渲染结果。
3. 用户提供的参考截图。
4. Nuum 已有的主题 token 和组件约定。
5. 实现者的主观推测。

截图用于判断视觉意图，但不能作为业务字段、数据结构或功能能力的依据。

参考 Grokbot 时应先检查实际源码，并在存在选择器覆盖或生成样式时核对最终计算样式，避免仅凭截图或单个 CSS 声明猜测字体、间距或组件状态。如果本地参考仓不可用，应明确说明并基于现有 token 保守实现。

## 2. 数据边界

UI 只能展示和编辑 Nuum 已真实拥有的数据。

- 新增字段前必须先检查 `@nuum/protocol` 的 schema。
- 可编辑字段必须有明确的 Host 读取、保存和刷新链路。
- 修改名称、描述、头像等字段后，所有投影位置应同步刷新。
- 不得因为参考产品存在标签、语音、速度等设置，就默认 Nuum 也存在。
- UI 投影不能创建第二份会话真源。
- Agent 间通信仍来自 Agent transcript，只改变展示方式，不复制记录。

## 3. 字体与文本

字体是界面可读性的一部分，不能通过全局增粗或统一降重来追求视觉接近。

- 字体栈、抗锯齿、字号、行高和字重必须作为一组共同校准。
- 调整前应核对 Grokbot 的最终计算样式，而不是只读取某一条局部规则。
- 正文、辅助信息、名称、标题和语义强调必须形成稳定层级。
- 禁止用全局 `font-weight` 修复单个组件看起来过细或过粗的问题。
- 禁止凭感觉引入 `550`、`650` 等非标准字重；只有在参考实现和目标平台均能稳定呈现时才可使用。
- 普通消息气泡不得因为背景颜色而自动加粗；Markdown 强调应保留自身语义。

本节的具体字体栈与字重表将在完成 Grokbot 运行时计算样式对照后补充。在此之前，字体改动应保持局部、可回退，并附实际 Electron 窗口对比结果。

## 4. 密度与间距

界面以 4px 为基础网格，优先使用以下间距：

```text
4 / 8 / 12 / 16 / 24px
```

- 同一组件内部优先使用 4–8px。
- 相邻设置项或列表项优先使用 8px。
- 不同内容分组之间使用 16–24px。
- 避免为了“高级感”加入大面积无功能留白。
- 紧凑不等于拥挤；正文仍需保持明确行高。

基础控件高度优先使用：

```text
24 / 28 / 32 / 36px
```

## 5. 侧边栏

- 顶部搜索和新建入口使用相同尺寸的圆形描边按钮。
- 图标使用正常细线，不通过加粗 stroke 制造强调。
- 当前选中项使用完整的高对比度背景面强调。
- 不使用单独的左侧竖线作为主要选中标识。
- NunuBar 在侧边栏中沿用会话行的视觉语言。
- NunuBar 头像使用成员头像拼贴，不使用损坏图片或独立占位逻辑。
- 底部设置入口与顶部控制按钮使用同一套圆形按钮语言。

## 6. 聊天工作区

- 顶部不显示横向分割线。
- Agent 信息入口使用浮雕感圆角胶囊按钮。
- 聊天内容滚动进入顶部按钮区域时，应逐渐淡出，避免文字直接穿过按钮。
- 消息时间作为独立时间层级展示。
- 输入区应保持轻量，不抢占会话正文的视觉焦点。

## 7. Agent 间通信

`SendToAgent` 一类通信不是 NunuBar 群聊。

主会话中：

- 收起为“已发消息给 ××”或“消息来自 ××”。
- 摘要可点击，但不直接展开完整消息正文。

通信子页面：

- 使用只读的双 Agent 会话渲染。
- 不提供继续发送消息的输入框。
- 顶部展示双方头像、名称和通信方向。
- 有少量消息时，高度只覆盖现有内容。
- 消息增加时逐步增高，但不得占满整个窗口。
- 达到最大高度后内部滚动。
- 从底部弹出，动效与 NunuBar 聊天面板保持一致。
- 不显示右上角关闭按钮。
- 点击面板外区域关闭。
- 可以保留底部“关闭聊天”操作作为显式退出入口。

## 8. 设置界面

设置弹层采用紧凑双栏结构：

```text
弹层：860 × 620px，上限为视口减 32px
左侧导航：190px
标题栏：54px
内容内边距：24px
分组间距：24px
设置项间距：8px
```

- 每个设置项是独立的紧凑卡片。
- 卡片最小高度约 44px，内边距约 12–13px。
- 输入框、选择器和按钮高度约 28px。
- 控件圆角约 6px，设置卡片圆角约 9px。
- 不复制 Nuum 不具备的参考产品设置。

## 9. 组件与主题

- 优先使用 `--nuum-*` 主题 token。
- 不在业务组件中重新定义系统级字体和颜色。
- 相同语义的按钮必须复用同一组件或样式变体。
- 新图标应进入统一图标注册表。
- 图标默认使用细线轮廓，并继承文本颜色。
- 除品牌色、状态色或外部内容外，避免在组件内写死颜色。
- 浅色和深色模式必须保持相同的层级关系。

## 10. 动效

动效应表达层级或状态变化，不作为装饰。

- hover 约 120–150ms。
- 面板进入约 220–300ms。
- 优先使用 `cubic-bezier(.22, 1, .36, 1)` 一类快速收敛曲线。
- 必须支持 `prefers-reduced-motion`。
- 不要让文字、列表和常驻按钮持续漂浮或缩放。

Nunu 的材质、颜色、形状、Logo、资料卡跟随与角色动画另见 [Nunu 与品牌规范](./nunu-brand.md)。

## 11. UI 检查清单

- [ ] 正文、辅助信息、名称与标题的层级清晰且没有笔画黏连。
- [ ] 浅色与深色模式均可读。
- [ ] 当前选中项明确。
- [ ] hover、focus、disabled 状态完整。
- [ ] 窄窗口没有溢出或遮挡。
- [ ] 弹层能通过预期方式关闭。
- [ ] UI 没有展示协议中不存在的字段。
- [ ] 数据修改后，所有投影位置同步更新。
- [ ] 已在实际 Electron 窗口中完成视觉验证。
- [ ] typecheck、相关测试和依赖边界检查通过。
